# Lessons from the approver
The editor reads this before every post. Written automatically from rejections; newest last.

- [BUILD YOUR COLLECTION] Before writing any stage JSON, read that stage's validator for required fields and allowed enum values; copy them exactly.
- [BUILD YOUR COLLECTION] When a validator rejects a value, switch to a value from its accepted list and rerun; never guess unlisted values across retries.
- [BUILD YOUR COLLECTION] If a retailer or brand page returns 429 or 403, switch to another official brand page or authorized retailer; never ship with unrecorded prices.
- [BUILD YOUR COLLECTION] Each product in a build-your-collection post needs a recorded price and an opened URL; drop any pick lacking both.
- [CELEBRITY COLLECTION] Name a specific celebrity and cite two or more dated watch sightings from trusted outlets before drafting; search more names if none qualify.
- [CELEBRITY COLLECTION] If a celebrity's sightings are older than the current month, find newer ones or switch to a different idea format.
- [CELEBRITY COLLECTION] Count a sighting only if you opened the article and read the model names; paywalled or redirected pages don't qualify, so find another source.
- [CELEBRITY COLLECTION] Every model, reference and price in a celebrity post must come from an opened, ungated source logged in the evidence file; otherwise drop that watch.
- [CELEBRITY COLLECTION] When a sighting article is gated or redirects, find another outlet covering the same sighting and open it first.
- [CELEBRITY COLLECTION] Log every gated or redirected URL in the evidence file with its celebrity, so retries skip those dead ends instead of rechecking them.
- [LISTICLE] Count distinct collections, not references: two references from one collection (e.g. two Le Locle refs) fill only one listicle slot.
- [LISTICLE] Before research, widen the brand list or price band until verified distinct collections reach the minimum; never fill slots with repeat collections.
- [LISTICLE] Use only cut-out or transparent-background product photos, or photos whose background matches the slide. Check every slide render for stray boxes.
- [LISTICLE] Give the cover slide a named watch photo whenever its visual job calls for one. Place the product image there before rendering.
- [LISTICLE] No watch may repeat across slides, including the cover. Check each slide's reference and collection against all others before rendering.
- [LISTICLE] When revising, apply every listed fix to the project files, re-render, and confirm the draft status changes from 'stopped' before resubmitting.
- [WOULD YOU RATHER] Before rendering, credit each slide's footer only to the source that supplied its figures, and check every headline's numbers against the listed prices.
- [WOULD YOU RATHER] Before picking a watch, check posts from the last 7 days and avoid any reference already featured; choose another within the price band.
- [WOULD YOU RATHER] Keep paired slide headlines to one line each so their values align; shorten any headline that wraps before rendering.
- [WOULD YOU RATHER] Use 'same money' framing only when both prices match exactly; otherwise state the actual gap or drop the framing.
