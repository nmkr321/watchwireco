# Lessons from the approver
The editor reads this before every post. Written automatically from rejections; newest last.

- [NEW RELEASES] Before drafting, name the release's niche, why it is timely now, and one save-or-share reason; if you can't, choose another release.
- [NEW RELEASES] On covers, keep the watch clear of headline text and use an even gradient; move the text block to a clear zone before rendering.
- [NEW RELEASES] Confirm each release date and price on a fetched page; search snippets don't count. Missing one? Find a second fetched source or omit it.
- [NEW RELEASES] Choose a release only when its official page shows the release date; otherwise pick a release whose date is confirmed.
- [NEW RELEASES] For release news, treat third-party roundups only as leads; fetch the brand's own press page before choosing or naming a release.
- [NEW RELEASES] After one search pass finds no dated official release, switch to a brand newsroom that lists release dates instead of repeating searches.
- [LISTICLE] Take product-page URLs from the brand's collection or search page, never from guessed slugs; a 404 means find the real URL.
- [LISTICLE] After a failed URL, make at most one replacement from a search or brand listing page; otherwise drop that item, don't retry slug variants.
- [LISTICLE] Pick one retailer or brand category page that lists several items with prices, and fetch it first, so one fetch can yield multiple fetched prices.
- [LISTICLE] Library prices dated within 7 days (read by the engine from official pages) count as verified: cite the library source URL and date; fetch fresh only for watches not in the library.
- [LISTICLE] Register every photo in assets/manifest.json with rights and exact credit before rendering; drop any photo that can't be registered.
- [LISTICLE] Before rendering, check that cover photo, slide labels and call to action match the plan and caption; fix any mismatch first.
- [LISTICLE] Use unique, non-repeating pick labels across all tiers in comment prompts and slides, e.g. 1 to 6, so a reply maps to one item.
- [LISTICLE] Before finishing the caption, list every claim and source ID used in the slides and caption; make the ID lists match exactly.
- [LISTICLE] Before rendering, view each slide's photo and confirm the watch is clearly visible; replace blank or unrelated images, or drop that item.
- [LISTICLE] Count slide body words before rendering and trim any over 15. Put a numbered comment prompt on the CTA slide and in the caption.
- [LISTICLE] After any slide or caption edit, re-render every preview and delete previews for removed slides so previews match the project's slide count and CTA.
- [LISTICLE] Use only adjectives and style claims a fetched source states; otherwise cut them, leaving price, date and spec facts only.
- [LISTICLE] Before rendering, produce research.json with research-agent origin, browser trace, specialist analysis and governance ledgers, then run validate and clear every error.
- [LISTICLE] Run validate after research, before drafting slides; if it lists missing records, generate each record from the fetched sources and re-run it.
